Base de données
---------------
Moteur : PostgreSQL (Supabase, service géré).
Table  : rondol_state(key TEXT PRIMARY KEY, payload JSONB) — snapshot d'état validé (profil de vis,
         consignes thermiques, feeders, calibrations). Index : PRIMARY KEY (B-tree) + index GIN sur payload.
Tables : app_users, login_history — authentification (mot de passe haché PBKDF2-HMAC-SHA256, jamais en clair).
Identifiants de connexion à la base (URL projet + clé API) : fournis séparément, NON versionnés (sécurité).

Persistance — état de configuration (à vérifier après config des secrets)
-------------------------------------------------------------------------
Sans secrets Supabase : backend_name()='local-json', is_durable()=False (NON durable, repli local).
Avec secrets Supabase : backend_name()='supabase', is_durable()=True (durable, survit au reboot Cloud).
Commande de preuve    : python scripts/verify_supabase.py

Lancement local (le jury peut relancer)
---------------------------------------
1. pip install -r requirements.txt
2. streamlit run app/Supervision.py
3. Health check : http://localhost:8501/_stcore/health  ->  HTTP 200
4. Connexion requise dès l'ouverture (identifiants de test : PDR_README.md section 7). En local sans
   Supabase configuré, le compte de démonstration est créé automatiquement au premier lancement.
